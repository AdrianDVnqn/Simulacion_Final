Parte 1 — Generación de Números Pseudoaleatorios y Monte Carlo

Implementación de un LCG

El Generador Congruencial Lineal (LCG) sigue la recurrencia:

\[X_{n+1} = (a \cdot X_n + c) \mod m, \quad U_n = X_n / m\]

Se implementan dos conjuntos de parámetros: uno de calidad reconocida (glibc/ANSI C) y uno defectuoso (RANDU).

Implementación en R

Código 
lcg <- function(n, seed = 42, a, c, m) {
  x <- numeric(n)
  x[1] <- (a * seed + c) %% m
  for (i in 2:n) x[i] <- (a * x[i-1] + c) %% m
  x / m
}

N <- 10000

# Parámetros "buenos" — glibc / ANSI C
u_good <- lcg(N, a = 1103515245, c = 12345, m = 2^31)

# Parámetros "malos" — RANDU (IBM, falla espectral en 3D)
u_bad  <- lcg(N, a = 65539, c = 0, m = 2^31)

Implementación en Python

Código 
def lcg(n, seed=42, a=1103515245, c=12345, m=2**31):
    x = seed
    seq = []
    for _ in range(n):
        x = (a * x + c) % m
        seq.append(x / m)
    return np.array(seq)

N = 10_000
u_good_py = lcg(N)
u_bad_py  = lcg(N, a=65539, c=0, m=2**31)

1.2 Estimación de π por Monte Carlo

Se generan \(N\) puntos uniformes en \([0,1]^2\) y se estima:

\[\hat{\pi} \approx 4 \cdot \frac{\#\{x_i^2 + y_i^2 \le 1\}}{N}\]

La estimación de \(\pi\) converge hacia el valor teórico (línea roja punteada en Figura 3) a medida que aumenta el número de simulaciones. Las oscilaciones observadas son inherentes al error Monte Carlo y disminuyen a razón de \(1/\sqrt{N}\) en media. El gráfico de convergencia ilustra claramente este comportamiento asintótico.

El diagrama de dispersión (Figura 4) confirma geométricamente la lógica del método: la frontera del círculo (línea negra) separa los puntos dentro de los que están fuera. La proporción observada de puntos verdes (dentro) aproxima la razón de áreas, \(\frac{\text{área del cuarto de círculo}}{\text{área del cuadrado}} = \frac{\pi/4}{1} = \pi/4\), de donde obtenemos la estimación multiplicando por 4.

Con \(N = 50000\) simulaciones, hemos obtenido una estimación muy cercana al valor teórico, con un error del orden de \(10^{-3}\). Para aplicaciones que requieran mayor precisión, bastaría escalar \(N\) según la tolerancia deseada, confirmando que el método es efectivo aunque computacionalmente costoso en dimensiones altas.

Conclusión de la Parte 1: la evidencia empírica sugiere que el generador bueno y la estimación de \(\pi\) cumplen con el comportamiento esperado, mientras que RANDU exhibe fallas estructurales incompatibles con su uso en simulación seria. Esta parte muestra la importancia de combinar observación gráfica, pruebas estadísticas e interpretación teórica para evaluar resultados simulados.

Parte 2 — Metropolis–Hastings y Bayesian Inference

2.1 Posterior beta analítica

Sea una moneda con \(n = 10\) lanzamientos y \(k = 7\) caras, con prior \(\text{Beta}(1, 1)\) (uniforme). La posterior conjugada es:

\[\theta \mid \text{datos} \sim \text{Beta}(\alpha + k,\ \beta + n - k) = \text{Beta}(8, 4)\]

La media posterior es \(\hat{\theta} = 8/12 \approx 0{.}667\).

2.2 Implementación Metropolis–Hastings

Código 
# Implementación básica de Metropolis-Hastings para muestrear la posterior de theta.
mh <- function(n_iter = 5000, start = 0.5, prop_sd = 0.1, seed = NULL) {
  if (!is.null(seed)) set.seed(seed)
  # Vector donde se guarda toda la cadena MCMC.
  theta    <- numeric(n_iter)
  # Condición inicial de la cadena.
  theta[1] <- start
  # Contador para estimar la tasa de aceptación.
  aceptados <- 0

  for (t in 2:n_iter) {
    # Propuesta local normal alrededor del estado anterior.
    prop <- rnorm(1, theta[t-1], prop_sd)

    # Rechazamos automáticamente propuestas fuera del soporte [0,1].
    if (prop < 0 || prop > 1) {
      theta[t] <- theta[t-1]
    } else {
      # Razón de aceptación: verosimilitud multiplicada por el prior.
      num   <- dbinom(7, 10, prop)      * dbeta(prop, 1, 1)
      den   <- dbinom(7, 10, theta[t-1]) * dbeta(theta[t-1], 1, 1)
      alpha <- min(1, num / den)

      # Aceptar o rechazar según una uniforme(0,1).
      if (runif(1) < alpha) {
        theta[t] <- prop
        aceptados <- aceptados + 1
      } else {
        theta[t] <- theta[t-1]
      }
    }
  }
  list(chain = theta, tasa_aceptacion = aceptados / (n_iter - 1))
}

# Cadena principal para una corrida larga de la simulación.
res     <- mh(n_iter = 10000, seed = 42)
# Cadena completa generada por MH.
cadena  <- res$chain
# Primer tramo descartado para eliminar dependencia de la inicialización.
burn_in <- 1000
# Cadena que sí se usa para inferencia posterior al burn-in.
cadena_post_burnin <- cadena[(burn_in + 1):length(cadena)]

# Mostrar cuánto de la cadena fue aceptado por el algoritmo.
cat(sprintf("Tasa de aceptación: %.2f%%\n", res$tasa_aceptacion * 100))
Tasa de aceptación: 77.78%

Parte 3 — Simulación de Eventos Discretos (M/M/1)

3.1 Introducción a Sistemas M/M/1

Un sistema M/M/1 es un modelo de colas donde: - M (primer símbolo): Las llegadas de clientes siguen un proceso de Poisson (tiempos entre llegadas exponenciales) - M (segundo símbolo): El servicio tiene duración exponencial - 1: Hay un único servidor

Este es el modelo de colas más simple pero fundamental en teoría de colas y es exactamente resoluble analíticamente. En la práctica, modela situaciones como: - Atención al cliente en un mostrador único - Procesamiento de solicitudes en un servidor web - Servicios en una ventanilla bancaria

Simulación de eventos discretos (DES): En lugar de resolver ecuaciones diferenciales, simulamos explícitamente los eventos (llegadas y salidas) ordenados en el tiempo. Esto permite estudiar sistemas dinámicos complejos sin soluciones cerradas y es el método standard en investigación operativa.

Parámetros del sistema:

  • Llegadas Poisson: \(\lambda = 10\) clientes/hora
  • Servicio exponencial: \(\mu = 4\) clientes/hora
  • Tiempo de simulación: \(T_{max} = 8\) horas

Análisis teórico: La tasa de utilización es \(\rho = \lambda/\mu = 2.5 > 1\). Esto indica que el sistema no es estable con un único servidor: los clientes llegan más rápido de lo que se pueden servir, causando que la cola crezca indefinidamente. Teóricamente, esta configuración viola las condiciones de estabilidad de la teoría de colas.

Caso estable: Con \(c = 3\) servidores en paralelo, \(\rho/c = 2.5/3 \approx 0.83 < 1\), y el sistema alcanza un equilibrio estacionario.

3.2 Algoritmo de Simulación de Eventos Discretos

El enfoque de simulación por eventos mantiene un reloj de simulación y procesa eventos ordenados por tiempo:

  1. Estado: Se registra el número de clientes en el sistema y los tiempos del próximo evento (llegada o salida).
  2. Eventos: En cada paso, se ejecuta el evento que ocurre primero:
    • Llegada: Un nuevo cliente entra. Si el servidor estaba libre, comienza el servicio inmediatamente.
    • Salida: Un cliente termina el servicio. Si hay cola, el siguiente cliente comienza.
  3. Salidas observadas: Se registra la longitud de la cola después de cada evento para visualizar la dinámica temporal.

Este método es eficiente porque salta directamente entre eventos sin simular tiempo “vacío”, a diferencia de la simulación discreta con pasos fijos.

Código 
# Función de simulación por eventos discretos para un sistema M/M/1
# Parámetros:
#   lambda: tasa de llegadas (proceso de Poisson)
#   mu: tasa de servicio (exponencial)
#   T_max: tiempo de simulación en horas
#   seed: semilla para reproducibilidad
simulate_mm1 <- function(lambda, mu, T_max, seed = 42) {
  set.seed(seed)
  
  # Inicialización de variables de estado
  t        <- 0              # Reloj de simulación
  n        <- 0              # Número de clientes en el sistema
  t_arr    <- rexp(1, lambda) # Tiempo del próximo evento de llegada
  t_dep    <- Inf            # Tiempo del próximo evento de salida (infinito inicialmente)
  arrivals <- departures <- 0 # Contadores de eventos
  wait_times   <- c()         # Vector para tiempos de espera (futuro uso)
  queue_length <- data.frame(time = 0, n = 0) # Historial: tiempo vs longitud de cola

  # Loop principal de simulación: continúa hasta exceder T_max
  while (t < T_max) {
    # Comparar próximos eventos: ¿qué sucede primero, llegada o salida?
    if (t_arr < t_dep) {
      # EVENTO: LLEGADA DE CLIENTE
      t      <- t_arr           # Adelantar reloj al tiempo de llegada
      n      <- n + 1           # Incrementar clientes en el sistema
      arrivals <- arrivals + 1  # Contador de llegadas totales
      
      # Si el servidor estaba libre (n=1 significa que este es el primer cliente)
      # programar una salida generando tiempo de servicio exponencial
      if (n == 1) t_dep <- t + rexp(1, mu)
      
      # Generar próximo evento de llegada usando distribución exponencial
      t_arr  <- t + rexp(1, lambda)
    } else {
      # EVENTO: SALIDA DE CLIENTE
      t      <- t_dep           # Adelantar reloj al tiempo de salida
      n      <- n - 1           # Decrementar clientes en el sistema
      departures <- departures + 1 # Contador de salidas totales
      wait_times <- c(wait_times, t) # Registrar tiempo de salida
      
      # Si hay clientes esperando, programar salida del siguiente
      # Si no hay clientes (n=0), no hay salida próxima (t_dep = Inf)
      t_dep  <- if (n > 0) t + rexp(1, mu) else Inf
    }
    
    # Registrar el estado actual (longitud de cola) en el historial
    queue_length <- rbind(queue_length, data.frame(time = t, n = n))
  }

  # Retornar lista con estadísticas y datos observados
  list(
    arrivals   = arrivals,           # Total de clientes que llegaron
    departures = departures,         # Total de clientes que se fueron
    wait_times = wait_times,         # Tiempos de salida (aproximación a tiempos de espera)
    queue_length = queue_length,     # Datos para graficar evolución de la cola
    rho        = lambda / mu         # Utilización del servidor
  )
}

3.4 Conclusión

Sistema Inestable (ρ = 2.5 > 1):

El experimento de simulación valida la teoría de colas: un sistema M/M/1 con \(\rho > 1\) es fundamentalmente inestable. La cola no alcanza un equilibrio sino que crece indefinidamente en promedio. En 8 horas, observamos 37 clientes acumulados, reflejando claramente esta dinámica. Esto es más que una inestabilidad matemática; tiene implicaciones prácticas directas:

  • En un servicio real (banco, consultoría, helpdesk), esto significa tiempos de espera crecientes y clientes insatisfechos.
  • No hay un estado estacionario; el sistema nunca “se estabiliza”.
  • Las métricas teóricas (Lq, L, Wq) ni siquiera se pueden calcular para \(\rho > 1\) (fórmulas divergen).

Sistema Estable (ρ = 0.75 < 1):

En contraste, si reducimos la tasa de llegadas a λ=3 clientes/hora (manteniendo μ=4), obtenemos \(\rho = 0.75 < 1\). En este caso: - Lq teórico ≈ 2.25 clientes en cola (en promedio, en equilibrio) - L teórico ≈ 3 clientes en el sistema - Wq teórico ≈ 0.75 horas de espera promedio en cola

Estos valores convergentes indican un sistema en equilibrio estacionario, donde las colas se autorregulan. Esta es la situación deseada en la práctica y la única donde la teoría de colas proporciona modelos predecibles.

Lección clave: La simulación de eventos discretos permite “ver” el comportamiento dinámico que la teoría predice. En ingeniería de sistemas, esto justifica inversiones en infraestructura: en sistemas sobrecargados (\(\rho > 1\)), la única solución es aumentar capacidad (μ) o reducir demanda (λ), no optimizar el algoritmo.

Parte 4 — Modelos Continuos

Se elige la Opción C: SDE — Movimiento Browniano Geométrico (GBM)

SDE — Geometric Brownian Motion

En esta sección trabajamos con el Movimiento Browniano Geométrico (GBM), uno de los modelos continuos más usados para describir la evolución de precios de activos, tasas de crecimiento poblacional o cualquier magnitud que sea estrictamente positiva y tenga variaciones proporcionales a su propio nivel.

La idea central del GBM es combinar una tendencia media de crecimiento o decrecimiento con una fuente de aleatoriedad que se acumula en el tiempo. Eso produce trayectorias suaves, pero no deterministas, y una distribución final asimétrica, típicamente log-normal.

Desde el punto de vista de simulación, este modelo es útil porque permite contrastar:

  • el comportamiento de trayectorias individuales frente a la media teórica,
  • la forma de la distribución simulada al final del horizonte,
  • y la diferencia entre una descripción puntual del proceso y su comportamiento agregado.

La ecuación diferencial estocástica es:

\[dS_t = \mu S_t\, dt + \sigma S_t\, dW_t\]

con \(\mu = 0.05\), \(\sigma = 0.2\), \(S_0 = 100\).

La solución analítica es:

\[S_t = S_0 \exp\!\left[(\mu - \frac{\sigma^2}{2})t + \sigma W_t\right]\]

Código 
# Dependencias necesarias para esta simulación.
import numpy as np
import matplotlib.pyplot as plt

# Parámetros del GBM.
# μ controla la deriva promedio del proceso, σ mide la intensidad de la volatilidad
# y S0 fija el nivel inicial desde el que parten todas las trayectorias.
mu    = 0.05
sigma = 0.20
S0    = 100.0
T     = 1.0      # 1 año
N_t   = 252      # pasos (días de trading)
M     = 1000     # trayectorias

# Paso temporal y grilla de tiempo para la simulación.
dt   = T / N_t
t    = np.linspace(0, T, N_t + 1)

# Generamos innovaciones gaussianas independientes para cada paso y trayectoria.
np.random.seed(42)
Z = np.random.standard_normal((N_t, M))
S = np.zeros((N_t + 1, M))
S[0] = S0

# Esquema de Euler-Maruyama:
# actualiza el nivel del activo multiplicando por el término determinista
# y por el choque estocástico escalado por sqrt(dt).
for i in range(N_t):
    S[i+1] = S[i] * (1 + mu * dt + sigma * np.sqrt(dt) * Z[i])

# ── Gráfico 1: trayectorias ──────────────────────────────────────────────────
fig, ax = plt.subplots(figsize=(7, 4))

# Trayectorias individuales: se muestran solo 100 para no saturar la figura.

ax.set_ylabel("Precio $S_t$")

Interpretación de resultados

Los resultados esperados para este experimento son coherentes con la teoría del GBM. En la Figura 10, las trayectorias individuales fluctúan alrededor de la tendencia media, pero no la siguen de manera exacta: eso refleja el efecto acumulativo del ruido browniano. A medida que avanza el tiempo, la dispersión entre trayectorias crece, lo que es consistente con una volatilidad proporcional al nivel del activo.

En la Figura 11, la distribución de \(S_T\) debe verse asimétrica y sesgada hacia la derecha, con una forma muy cercana a la curva log-normal teórica. Esa coincidencia es importante porque valida que la simulación reproduce no solo una trayectoria típica, sino también la distribución terminal del proceso.

La comparación entre momentos teóricos y simulados permite medir la calidad del esquema de Euler-Maruyama. Si la media y la varianza simuladas quedan cerca de sus valores analíticos, entonces la discretización está capturando correctamente la dinámica del modelo para el paso temporal elegido.

Discusión

Este ejercicio muestra dos ideas relevantes. Primero, en un proceso estocástico continuo no basta con mirar una trayectoria aislada: una sola realización puede terminar por encima o por debajo de la media teórica sin que eso contradiga el modelo. Lo importante es el comportamiento agregado de muchas trayectorias.

Segundo, la elección de \(\sigma\) tiene un impacto central. Con una volatilidad mayor, la dispersión final aumenta, la distribución se ensancha y la probabilidad de observar valores extremos se vuelve más alta. En contextos financieros, esto se traduce en mayor incertidumbre sobre el precio futuro.

También conviene remarcar que Euler-Maruyama es una aproximación numérica. Para pasos temporales pequeños funciona bien y resulta simple de implementar, pero si se quisiera mayor precisión podrían evaluarse esquemas más refinados o incluso la solución exacta del GBM, que en este caso es conocida.

Conclusión

La simulación confirma que el Movimiento Browniano Geométrico es un modelo adecuado para procesos positivos con crecimiento medio y fluctuaciones aleatorias proporcionales al nivel. Las trayectorias simuladas muestran variabilidad creciente, la distribución terminal tiene la forma esperada y las magnitudes agregadas se alinean con la teoría.

Esta sección ilustra cómo un modelo continuo puede analizarse simultáneamente desde tres niveles: trayectoria, distribución y momentos. Esa combinación de simulación e interpretación es la que hace útil al GBM como herramienta básica para estudiar fenómenos con incertidumbre continua.

Parte 5 — Gillespie SSA

Sistema de transcripción de mRNA

El sistema modela la producción y degradación de mRNA:

\[\emptyset \xrightarrow{k_1} \text{mRNA} \qquad \text{mRNA} \xrightarrow{k_2} \emptyset\]

con \(k_1 = 10\) (producción) y \(k_2 = 1\) (degradación). El estado estacionario teórico es \(\bar{X} = k_1/k_2 = 10\).

Código 
gillespie <- function(Tmax, k1 = 10, k2 = 1, seed = 42) {
  set.seed(seed)
  t  <- 0
  X  <- 0L
  ts <- numeric(1e6)
  xs <- integer(1e6)
  idx <- 1L
  ts[idx] <- t;  xs[idx] <- X

  while (t < Tmax) {
    a1 <- k1
    a2 <- k2 * X
    a0 <- a1 + a2

    if (a0 == 0) break           # estado absorbente (imposible aquí por k1>0)

    tau <- rexp(1, rate = a0)
    t   <- t + tau

    if (t > Tmax) break

    if (runif(1) * a0 < a1) {
      X <- X + 1L
    } else {
      X <- max(0L, X - 1L)
    }

    idx <- idx + 1L
    ts[idx] <- t
    xs[idx] <- X
  }

  data.frame(time = ts[1:idx], X = xs[1:idx])
}

nhpp_thinning <- function(Tmax, lambda_fun, lambda_max, seed = 42) {
  set.seed(seed)
  t <- 0
  arrivals <- c()

  while (TRUE) {
    t <- t + rexp(1, rate = lambda_max)
    if (t > Tmax) break
    if (runif(1) < lambda_fun(t) / lambda_max) arrivals <- c(arrivals, t)
  }

  arrivals
}

simulate_biomarker <- function(Tmax, k1 = 10, k2 = 1, seed = 42) {
  set.seed(seed)
  t  <- 0
  X  <- 0L
  ts <- c(t)
  xs <- c(X)

  while (t < Tmax) {
    a1 <- k1
    a2 <- k2 * X
    a0 <- a1 + a2
    tau <- rexp(1, rate = a0)
    t <- t + tau
    if (t > Tmax) break
    if (runif(1) * a0 < a1) {
      X <- X + 1L
    } else {
      X <- max(0L, X - 1L)
    }
    ts <- c(ts, t)
    xs <- c(xs, X)
  }

  data.frame(time = ts, X = xs)
}

sample_biomarker_at <- function(path, t_query) {
  idx <- findInterval(t_query, path$time)
  path$X[pmax(1, idx)]
}
